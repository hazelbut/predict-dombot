# Predict Terminal — торговля в стакане predict.fun кликами

Локальный терминал для рынков **BTC Up/Down 5m и 15m** на predict.fun, напрямую через их API:

- **два стакана-лесенки (UP и DOWN)** по живому WebSocket predict.fun; для каждой цены видно объём (шт) и
  накопленную сумму `Σ$` — сколько стоит выкупить всё до этой цены;
- **один клик = ордер**, без подтверждений и всплывающих окон кошелька (ордер подписывается ключом локально);
- **график BTCUSDT как в Binance**: японские свечи или линия, таймфреймы 1s/1m/3m/5m/15m/1h/4h, зум колесом,
  прокрутка мышью с подгрузкой истории, линия стартовой цены рынка и метки старт/конец;
  - **цены UP и DOWN predict.fun** на левой шкале (кнопки `UP` / `DOWN`, можно обе): ступенчатая линия по середине стакана,
    вертикальный скачок = цена исхода резко сдвинулась внутри свечи;
  - **индикаторы:** три EMA, Bollinger (20, 2), RSI (14) в панели под графиком — периоды меняются прямо на панели;
  - **пузыри** маркет-покупок (зелёные) и продаж (красные) BTCUSDT за секунду; режимы: над/под свечой, сумма за свечу,
    на цене; порог «≥» в BTC (пусто — авто, 97-й перцентиль);
  - **ордера спотового стакана BTCUSDT** — горизонтальные полосы у правого края с объёмом в BTC; шаг «авто» держит строки
    читаемыми при любом масштабе (или выбери $1…$100 вручную); подсказка под курсором: диапазон цен, объём в BTC и $,
    сколько стоит до этого уровня от лучшей цены;
  - **плотности** — уровни крупнее среднего × N протягиваются линией через весь график;
  - **хитмап стакана** (как в xau_terminal) — история спотового стакана BTCUSDT под свечами: яркость = объём на уровне.
    Видно, как плотность стоит, переставляется или разъедается, на любом масштабе. Сервер хранит 30 минут, после
    перезагрузки страницы история на месте;
  - клавиши слоёв: `V` пузыри · `D` ордера · `W` плотности · `H` хитмап · `B` BB · `R` RSI.
- **давление в шапке**: красно-зелёная шкала с % и объёмом — «Стакан» (bid против ask в ±10/25/50/100 б.п. от цены) и
  «Маркет» (маркет-покупки против продаж за 10/30/60/300 с). Клик по шкале меняет диапазон;
- **размер окон**: перетаскивай разделители между графиком и стаканами, графиком и RSI, графиком и журналом.
  Двойной клик по разделителю — вернуть как было. Размеры запоминаются;
- таймер до конца рынка, **отрыв BTC от старта**, баланс, позиции с PnL, лимитки, журнал с задержками;
- **демо-режим** без ключей и денег — потренироваться с кликами.

Всё работает у тебя на компьютере (`http://127.0.0.1:8765`), наружу ничего не открыто.

## Управление

| Действие | Что произойдёт |
|---|---|
| **ЛКМ по ask-стороне** (правая половина строки) | купить этот исход **по рынку**: всё, что есть в стакане до этой цены, на сумму «Покупка $». Хуже кликнутой цены не исполнится |
| **ЛКМ по bid-стороне** (левая половина) | продать позицию **по рынку** до этой цены (25 / 50 / 100 % позиции) |
| **ПКМ или Shift+ЛКМ по bid-стороне** | лимитка **BUY** по этой цене (встаёт в стакан до конца рынка) |
| **ПКМ или Shift+ЛКМ по ask-стороне** | лимитка **SELL** по этой цене |
| клик по колонке «мои» | отменить свои лимитки на этой цене |
| **Esc** | отменить все лимитки текущего рынка |
| **F** | центрировать стаканы |
| «закрыть» в позициях | продать всю позицию по рынку (до 5 тиков ниже лучшего bid) |

Пока сверху горит **«ТОРГОВЛЯ ВЫКЛ»**, клики ничего не отправляют. Внизу справа подсказка показывает, что сделает
клик: сколько штук, за сколько, средняя цена, выигрыш при исходе в твою пользу.

Флажок **«только мейкер»**: лимитка не исполнится сразу как тейкер, только встанет в стакан (мейкер — без комиссии).

## Установка (Windows)

1. Python 3.10+ (если нет: python.org, галочка «Add to PATH»).
2. Распаковать архив, запустить `install_windows.bat`.
3. Попробовать без ключей: `start_demo_windows.bat` (деньги ненастоящие, стакан симулируется).
4. Для реальной торговли заполнить `.env` (см. ниже) и запустить `start_windows.bat`.
   Браузер откроется сам на `http://127.0.0.1:8765`.

## Ключи (`.env`)

Имена переменных те же, что в боте **pf_sniper** — можно просто скопировать его `.env` в папку терминала
(лишние переменные бота терминал игнорирует).

- `PREDICT_API_KEY` — predict.fun → раздел для разработчиков (developer dashboard): создать приложение и сгенерировать ключ.
- Вход **через почту / соцсеть** (Predict account):
  - `PREDICT_ACCOUNT` — адрес аккаунта (deposit address) из настроек predict.fun;
  - `PREDICT_PRIVATE_KEY` — приватный ключ кошелька Privy (Настройки → Export wallet).
- **Свой кошелёк** (Rabby/MetaMask): `PREDICT_ACCOUNT` пустой, в `PREDICT_PRIVATE_KEY` — ключ этого кошелька.

⚠️ Приватный ключ даёт полный доступ к деньгам аккаунта. Держи на аккаунте только торговую сумму, `.env` никому не отправляй.

Разрешения контрактам (approvals) должны быть выданы заранее. Если ты уже торговал через сайт predict.fun, они есть.

## Лимит запросов

predict.fun даёт **240 запросов в минуту на API-ключ**. Если бот и терминал работают на одном ключе — лимит общий.
Терминал расходует ~30–50 запросов в минуту (стакан и события идут по WebSocket, REST — только рынки и счёт);
текущий расход виден в шапке: `API N/240`. Для одновременной работы с ботом лучше завести второй ключ.

## Безопасность в коде

- `TERMINAL_MAX_ORDER_USDT` — максимум на один клик (по умолчанию 50$).
- Рыночный ордер подписывается с ценой не хуже кликнутой (`TERMINAL_SLIPPAGE_TICKS=0`); остаток не висит в стакане.
- Лимитки автоматически истекают в момент окончания рынка.
- Сервер слушает только `127.0.0.1`.

## Файлы

- `logs/trades.csv` — каждый отправленный ордер: время, рынок, сторона, цена, сумма, задержка, ответ биржи.
- `logs/terminal.log` — полный лог.

## На сервере вместо Windows

```
./install_linux.sh && nano .env && ./start_linux.sh
```
Открыть с Windows через SSH-туннель:
`ssh -L 8765:127.0.0.1:8765 trader@<сервер>` → в браузере `http://127.0.0.1:8765`.

## Тесты

```
pip install -r requirements-dev.txt && python -m pytest -q
```
Проверяют математику стакана, подпись ордеров (подписант восстанавливается из подписи), формат запросов и полный
цикл с фейковым сервером predict.fun (авторизация, рынки, WS, heartbeat, ордера, отмена).

## Бот «фаворит» (живая проверка бэктеста)

`run_favbot.py` — BTC Up/Down 5m: на 30–150 с окна, когда лучший аск одной стороны в 0.60–0.70, покупает её
(потолок аск + 1 тик) на 1.1$ и держит до конца окна. Один вход на окно. Выигрыши выкупаются в USDT on-chain
(газ BNB у кошелька-подписанта).

- без флагов — бумажный режим (ордера не отправляются); `--live` — реальные ордера;
- лимиты: −10$ за сутки UTC (пауза до следующих суток), −25$ всего (стоп), контрольные точки: 300 сделок и ROI < −3% → стоп,
  1000 сделок и ROI < +1% → стоп; открытые позиции считаются уже проигранными;
- пауза: создать `logs/favbot.STOP`; сброс учёта: удалить `logs/favbot_live.json`;
- журнал: `logs/favbot.log`, сделки `logs/favbot_live.csv`.

## Бот «стакан + дешёвые исходы» (DOM bot)

`run_dombot.py` — гибрид xau_terminal и pf_sniper: сигналы спотового стакана BTCUSDT (как в xau_terminal) +
исполнение на predict.fun (те же ключи `.env`, тот же API). Рынки BTC Up/Down 5m (или `--series 15m`).

**Правило входа** (всё сразу):
1. лучший аск стороны в **0.10–0.30**, спред ≤ 5 ц., до конца окна 30…270 с (для 15m — 30…870 с);
2. свежий (≤ 20 с) **сигнал стакана BTCUSDT в сторону этой стороны** и нет свежего сигнала против:
   - **СЪЕЛИ** — плотность ≥ $150k в ±25 б.п. разъели маркетом (съели биды → DOWN, аски → UP);
   - **СНЯЛИ** — плотность исчезла без сделок (сняли бид → DOWN, аск → UP);
   - **ДИСБ** — биды/аски в ±10 б.п. перекошены ≥ 60% и держится ≥ 3 с;
3. **модель справедливой вероятности** (из pf_backtest: цена BTC против цены старта, волатильность за 15/60 мин,
   оставшееся время) даёт этой стороне больше, чем стоит аск с комиссией, минимум на 2 ц. (`--min-edge`).

Держит до расчёта, одна позиция на окно, ставка 1.1$. Лимиты: −10$ за сутки UTC, −25$ всего, контрольные точки
300 сделок ROI < −10% и 1000 сделок ROI < 0 → стоп. Пауза: `logs/dombot.STOP`.

```
python run_dombot.py                 # PAPER: живые стаканы, без ордеров
python run_dombot.py --live          # реальные ордера
python run_dombot.py --demo          # офлайн-симулятор (проверить, что запускается)
python run_dombot.py --report        # калибровка по записанным кандидатам
```

**Кандидаты.** Каждый раз, когда сторона стоит в 0.10–0.30, бот пишет строку в `logs/dombot_candidates.csv`
(цена, модель, край, сигналы, дисбаланс, поток маркет-ордеров, максимум bid после, итог) — неважно, купил или нет.
`--report` показывает по группам (цена, с сигналом / без / против, тип сигнала, край модели, время до конца):
сколько раз сторона реально выиграла против того, сколько за неё платили, с 95% доверительным интервалом,
и как часто bid доходил до ×2 от цены входа (стоило бы продать раньше).

**Почему так, а не сразу live.** Покупка фаворита по 0.60–0.70 в бэктесте была в плюсе — значит та же сторона
стакана (андердог по 0.30–0.40) в среднем переоценена. Дешёвые исходы без дополнительной информации — минус.
Бот имеет смысл, только если в строке «с сигналом стакана» доля выигрышей уверенно выше цены. Исторического
стакана Binance нет, поэтому это проверяется только записью вперёд: набрать paper-данные (несколько сотен окон),
посмотреть `--report`, потом решать про `--live`, `--shift-bps`, `--kinds`.

Полезные настройки: `--kinds eaten,pulled` (без дисбаланса), `--no-signal` (только модель — контроль),
`--wall-min-usd 300000`, `--sig-ttl 10`, `--k 1.2` (масштаб волатильности), `--lo/--hi`.

Лимит API predict.fun общий для ключа (240/мин): бот + терминал на одном ключе — следи за `API N/240`
или заведи второй ключ.
