# predict-dombot

Бот и бэктест для рынков **BTC Up/Down 5m / 15m на [predict.fun](https://predict.fun)**.

Идея бота: покупать **дешёвый исход (0.10–0.30)**, если стакан Binance BTCUSDT показывает движение в его
сторону (крупную плотность разъели или сняли, сильный перекос бидов и асков), а модель справедливой вероятности
говорит, что исход стоит дороже своей цены с комиссией. Позиция держится до расчёта.

> ⚠️ Это исследовательский код, а не проверенная прибыльная стратегия. Важная оговорка: дешёвые исходы на этих
> рынках в среднем **переоценены**. Покупка фаворита по 0.60–0.70 — это та же сделка с другой стороны того же
> стакана, и она показывала плюс. Поэтому без дополнительного сигнала покупка андердогов — это минус. Бэктест
> ниже нужен как раз для того, чтобы проверить, перекрывает ли сигнал стакана этот перекос.

## Установка

Нужен Python 3.10+.

**Windows:** распаковать или клонировать, запустить `install_windows.bat`.
Дальше все команды выполняются из папки репозитория, Python берётся как `.venv\Scripts\python`.

**Linux / macOS:**
```
./install_linux.sh
```
Python берётся как `.venv/bin/python`.

Ключ: открыть `.env` (создаётся из `.env.example`) и вписать **только `PREDICT_API_KEY`**. Ключ берётся на
predict.fun → developer dashboard → создать приложение → сгенерировать ключ. Для бэктестов, рекордера и бота
в бумажном режиме больше ничего не нужно: ни кошелька, ни денег. Приватный ключ кошелька нужен только для
реальных ордеров.

Проверить, что всё установилось (55 тестов, сеть не нужна):
```
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

## Бэктест: три шага

Стакан Binance в прошлом нигде не хранится. Поэтому бэктест разделён на то, что можно проверить на истории
(шаг 1), и то, что приходится сначала записать (шаг 2).

### Шаг 1. История predict.fun, работает сразу

Проверяет цену (как часто исход по 0.10–0.30 реально выигрывает), фильтр модели бота и поток маркет-ордеров
Binance (агрессивные покупки против продаж — эта часть стакана в истории есть).

```
cd research
../.venv/bin/python collect.py --days 14          # сделки predict.fun за 14 дней (5m), ~1-2 ч, можно прерывать
../.venv/bin/python btc1s.py                      # секундные цены BTC с Binance
../.venv/bin/python btc_flow.py                   # поток маркет-ордеров BTC (необязательно; ~100 МБ/день загрузки)
../.venv/bin/python dog_history.py                # отчёт
```
На Windows то же самое, только вместо `../.venv/bin/python` пишется `..\.venv\Scripts\python`.
Для 15-минутных окон: `collect.py --series 15m`, `dog_history.py --series 15m`.

Как читать отчёт:
- **безуб.** — средняя цена входа с комиссией. Чтобы был плюс, **выигр** должен быть выше;
- **95% дов.** — доверительный интервал доли выигрышей. Если он перекрывает «безуб.», значит, это шум;
- **1-я пол / 2-я пол** — то же правило на первой и второй половине периода. Масштаб модели подбирается только
  на первой половине, поэтому вторая — честная проверка;
- строки «контроль» должны быть хуже основных, иначе фильтр ничего не делает.

### Шаг 2. Запись стакана и реплей бота

Рекордер пишет каждые 0.25 с то же, что видит бот: стакан BTCUSDT в ±40 б.п., сделки, цену, стаканы
predict.fun и итоги окон. Его нужно держать включённым **несколько дней подряд**, чтобы набрались сотни окон.

```
cd research
../.venv/bin/python dom_recorder.py --check       # 30 с: всё ли приходит
../.venv/bin/python dom_recorder.py               # пишет в research/data/dom/, остановка — Ctrl+C
```
На сервере удобно запускать в `tmux`. Файлы делятся по часам, перезапуск ничего не ломает: реплей пропускает
разрывы и после каждого из них даёт 15 минут на прогрев.

Реплей прогоняет код бота (`terminal/dombot.py`) по записи для сетки параметров: размер плотности, набор
сигналов, «свежесть» сигнала, минимальный край, сдвиг модели. Плюс контроль «без сигнала»:
```
../.venv/bin/python dom_replay.py
../.venv/bin/python dom_replay.py --from 2026-10-10 --to 2026-10-16 --k 1.1
../.venv/bin/python dom_replay.py --walls 150000 --kinds съели+сняли --ttls 20 --edges 0.02 --shifts 0
```
`--k` — масштаб волатильности. Его лучше взять из отчёта шага 1 (строка «модель: k = …»).
Главный вопрос к отчёту: **лучше ли варианты с сигналом, чем контроль «БЕЗ сигнала»**, и держится ли это
в обеих половинах. Вариантов много, поэтому лучший по ROI почти всегда завышен случайно.

### Шаг 3. Бот в бумажном режиме

```
.venv/bin/python run_dombot.py                    # живые стаканы, без ордеров, нужен только API-ключ
.venv/bin/python run_dombot.py --report           # калибровка по записанным ситуациям
.venv/bin/python run_dombot.py --demo             # офлайн-симулятор, без ключей и сети
```
Бот записывает каждую ситуацию «сторона стоит 0.10–0.30» с признаками и итогом в
`logs/dombot_candidates.csv`, независимо от того, купил он или нет. Все настройки: `run_dombot.py --help`.

Реальные ордера (`--live`) требуют `PREDICT_ACCOUNT` и `PREDICT_PRIVATE_KEY` и работают с реальными деньгами.
Включать их стоит только после шагов 1–2.

## Что где лежит

| | |
|---|---|
| `terminal/dombot.py` | бот: детектор сигналов стакана, модель вероятности, правило входа, журнал кандидатов, отчёт |
| `run_dombot.py` | запуск бота (paper / live / demo / report) |
| `research/collect.py`, `btc1s.py`, `btc_flow.py` | загрузка истории: predict.fun, цена BTC 1 с, поток маркет-ордеров |
| `research/dog_history.py` | шаг 1: бэктест на истории |
| `research/dom_recorder.py`, `dom_replay.py` | шаг 2: запись и реплей |
| `research/backtest.py`, `fair.py` | общая часть бэктеста (загрузка сделок, комиссия, модель) |
| `run_terminal.py`, `terminal/` | кликовый терминал predict.fun (см. `docs/TERMINAL.md`) |
| `run_favbot.py` | бот «фаворит» (покупка 0.60–0.70) |

Лимит API predict.fun — 240 запросов в минуту на ключ. `collect.py` по умолчанию тратит 120, рекордер и бот —
по нескольку в минуту. На одном ключе их можно запускать одновременно, но не вместе с несколькими копиями
`collect.py`.
